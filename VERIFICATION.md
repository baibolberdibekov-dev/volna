# Проверка архива

Проверено 25 октября 2026 года на Windows с Python 3.12.

- **31 автоматический тест прошёл.** Проверены входные данные, ключ доступа, лимиты запросов/очереди/хранилища, кэш поиска, статусы задач, удаление частичных и просроченных файлов, секрет ссылки, скачивание, HTTP Range и завершение дочернего процесса по тайм-ауту.
- `node --check static/app.js` — успешно.
- `pip check` — конфликтов установленных зависимостей не найдено.
- Реальный поиск через YouTube по запросу `youtube-dl test video` — получены результаты с метаданными.
- Реальный тестовый ролик `DTi8wZ1a1TA` получен и преобразован в MP3: **240 802 байта, 9,98 секунды, 192 000 бит/с, 44 100 Гц**. Формат и параметры проверены чтением MP3 через Mutagen.
- Полный HTTP-сценарий: поиск → создание задачи → статус ready → скачивание (`200`, `audio/mpeg`) → запрос части аудио для плеера (`206`).
- В браузере проверены поиск, выбор результата, переход к статусу «Готово к скачиванию», ссылка MP3 и отсутствие ошибок JavaScript. Проверены настольная и мобильная компоновки; на узком экране горизонтального переполнения нет.

Для локальной проверки использовались FFmpeg и Node.js 24 как поддерживаемый yt-dlp JavaScript runtime. В Docker предусмотрен Deno 2.9.8 и системные FFmpeg/ffprobe. Docker на проверочном компьютере отсутствует, поэтому **сборка/запуск Docker здесь не выполнялись**. Их проверка включена в `.github/workflows/check.yml` и запустится после загрузки репозитория при включённых GitHub Actions.

Развёртывание на Render не выполнялось: запрос был на ZIP для самостоятельной загрузки. Доступ YouTube с будущего сервера и его IP необходимо проверить после публикации. Успешная локальная проверка не гарантирует доступ к каждому ролику с любого хостинга.

Тестовая аудиозапись, временные файлы, виртуальное окружение и секреты в ZIP не включены. При тестировании был только один предупреждающий вывод библиотеки тестового клиента о будущем переходе с httpx; ошибок тестов не было.
