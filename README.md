# Волна — музыка с собой

Готовый сайт на русском: название песни → результаты YouTube → кнопка MP3 → подготовка и скачивание. Адаптивный интерфейс, обложки, длительность, выбор 128 / 192 / 320 кбит/с, прогресс, прослушивание готового файла и история поиска в браузере. YouTube API key не нужен.

**Начни с [START-HERE.txt](START-HERE.txt).** В архиве исходники, сервер, Docker и настройки развёртывания. Готовые песни и установленные зависимости в архив не входят: зависимости устанавливаются при сборке, песни загружаются по запросу.

## Публикация из GitHub

Альтернатива Blueprint: **New + → Web Service → репозиторий**, runtime **Docker**, Dockerfile `./Dockerfile`, health check `/api/health`. Порт приложение получает из `PORT`.

GitHub Pages размещает статические HTML/CSS/JS и не исполняет Python/FFmpeg. Для конвертации требуется сервер. Само добавление файлов в GitHub не создаёт работающий сервер. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

Free на Render подходит для проверки: сервис засыпает после простоя, первый запуск может занять около минуты, файлы исчезают при перезапуске, есть ограничения трафика и ресурсов. Проверь текущие условия в аккаунте. Для постоянного использования выбери подходящий сервер. [Ограничения Render Free](https://render.com/docs/free), [формат Blueprint](https://render.com/docs/blueprint-spec).

## Запуск на компьютере или VPS

Установи Docker с Compose, открой терминал в папке проекта:

```sh
docker compose up --build
```

Открой [http://localhost:8000](http://localhost:8000). Для запуска в фоне: `docker compose up --build -d`. Остановка: `docker compose down`. Логи: `docker compose logs -f`.

В Compose порт привязан к `127.0.0.1`. Для публичного VPS настрой HTTPS через свой reverse proxy к `127.0.0.1:8000`. Используй один контейнер приложения. Отдельная база данных не требуется.

Docker устанавливает Python, FFmpeg, ffprobe, Deno, yt-dlp и нужный пакет EJS автоматически. Не нужно отдельно собирать JavaScript или устанавливать Node.js для сайта. Deno и EJS нужны для текущей поддержки YouTube в yt-dlp. [Описание EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [образ Deno](https://github.com/denoland/deno_docker).

## Запуск без Docker для разработки

Нужны Python 3.12+, FFmpeg **и ffprobe** в PATH, Deno 2.3+ в PATH.

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

macOS / Linux:

```sh
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

Приложение доступно на порту 8000. При запуске без Docker переменные окружения задаются в терминале; `.env` автоматически не читается. Deno должен быть доступен тому же пользователю, который запускает сервер.

## Настройки

В Render добавляй переменные в **Environment**, затем перезапускай сервис. Для Docker Compose можно скопировать `.env.example` в `.env`: параметры, перечисленные в `compose.yaml`, будут переданы контейнеру. Остальные добавляй в `environment` этого файла.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_KEY` | пусто | Необязательный общий ключ доступа к поиску и подготовке MP3. После установки сайт покажет поле ввода. |
| `PORT` | `8000` | Порт HTTP; на Render задаётся `10000`. |
| `MAX_DURATION_SECONDS` | `1200` | Максимальная длительность: 20 минут. |
| `MAX_FILE_MB` | `80` | Лимит размера исходного и готового файла. |
| `MAX_CACHE_MB` | `512` | Бюджет временного хранилища, с резервом для активных задач. |
| `FILE_TTL_SECONDS` | `3600` | Срок хранения готового файла: час после завершения. |
| `DOWNLOAD_WORKERS` | `1` | Число одновременно обрабатываемых треков. |
| `MAX_JOBS` | `12` | Верхний предел активных/ожидающих задач; лимит хранилища может ограничить очередь раньше. |
| `JOB_TIMEOUT_SECONDS` | `300` | Максимальное время работы одной задачи, без ожидания очереди. |
| `SEARCH_TIMEOUT_SECONDS` | `60` | Максимальное время поиска. |
| `DATA_DIR` | `data` | Выделенная папка для временных файлов приложения. |
| `FFMPEG_LOCATION` | пусто | Необязательный путь к каталогу с FFmpeg и ffprobe. |

Ключ не требуется для обычного использования. Если устанавливаешь его, храни в настройках хостинга, не в GitHub. Браузер сохраняет ключ только для текущей вкладки. Ссылка готового файла содержит случайный секрет и действует до удаления файла; любой, у кого есть эта ссылка, может скачать файл.

Очередь, кэш поиска и статусы находятся в памяти. Запускай **один процесс/одну реплику** (`run.py` уже настроен так). Перезапуск сбрасывает задачи и удаляет их временные файлы. Автоматическая очистка проверяется каждые 30 секунд. Для масштабирования нужна отдельная очередь и общее хранилище.

Есть ограничение частоты поиска и подготовки на IP. За reverse proxy оно может применяться к общему IP прокси. Если нужно различать посетителей, настрой стандартный `FORWARDED_ALLOW_IPS` Uvicorn только на доверенные адреса прокси; не доверяй произвольным заголовкам из интернета.

## Если что-то не работает

| Ситуация | Что делать |
| --- | --- |
| Открывается GitHub README, а не сайт | Открывай адрес сервиса Render после развёртывания. GitHub хранит исходники. |
| Первый вход долгий | Подожди запуска сервиса после простоя. |
| YouTube просит вход или ограничивает запросы | Это ограничение источника/IP сервера. Попробуй позже, локальный запуск или другой хостинг. Код не гарантирует обход ограничений. |
| Поиск работает, конкретная песня не скачивается | Выбери другой результат: возможны региональные ограничения, удалённое видео, лимит длительности/размера или ограничения формата. |
| На компьютере работает, на сервере нет | Сравни доступ сервера к YouTube и версии yt-dlp/Deno; дата-центровый IP может ограничиваться. |
| Ошибка FFmpeg | В Docker всё включено. При ручной установке проверь `ffmpeg -version` и `ffprobe -version`. |
| Ссылка перестала работать | Файл хранится час и удаляется при перезапуске. Нажми MP3 ещё раз. |
| Очередь/хранилище заполнены | Подожди завершения/истечения файлов или увеличь лимиты при достаточных ресурсах сервера. |
| После изменений YouTube перестало работать | Обнови yt-dlp вместе с его зависимостями и пересобери образ. |

Для обновления yt-dlp замени его версию в `requirements.txt` на актуальную стабильную из [официальных выпусков](https://github.com/yt-dlp/yt-dlp/releases), сохраняя `[default]`, затем пересобери: `docker compose build --pull --no-cache` и `docker compose up -d`. На Render запусти развёртывание последнего commit с очисткой кэша сборки. Версии остальных зависимостей тоже следует периодически обновлять и проверять.

Нет обхода DRM, доступа к приватным/платным видео, автоматического входа в аккаунты или гарантии доступности каждого трека. Скачивай только аудио, на которое есть права или разрешение, с соблюдением правил источника. MP3 320 кбит/с не улучшит исходную запись с меньшим качеством.

## Проверки и устройство проекта

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

GitHub Actions запускает проверки Python, проверку синтаксиса JS, сборку Docker и проверку запуска контейнера. Тесты приложения изолированы от YouTube: они проверяют очередь, выдачу файлов, ошибки, лимиты и очистку. Доступ к YouTube зависит от окружения и требует отдельной проверки после публикации. Фактически выполненные проверки архива описаны в `VERIFICATION.md`.

- `app/main.py` — HTTP API, очередь, временные файлы, ограничения.
- `app/worker.py` — отдельный процесс поиска/получения аудио через yt-dlp и FFmpeg.
- `static/` — интерфейс без сборщика и сторонних CDN.
- `Dockerfile`, `compose.yaml`, `render.yaml` — запуск и хостинг.
- `tests/` — автоматические проверки.

Сайт передаёт поисковый запрос серверу, который обращается к YouTube; обложки браузер получает с YouTube. Недавние поиски хранятся локально в браузере и очищаются кнопкой «Очистить». Аналитика не подключена.
